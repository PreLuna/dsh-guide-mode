# 指导插件的任务边界与维持现状的设计

更新：2026-11-04（Asia/Shanghai）。依据用户本轮决定，区分原生组件职责、本插件接受的设计边界和真正需要继续维护的集成责任。本文件记录当前任务范围；测试事实以原始报告为准，范围调整不把 failed／未测改写为 passed。

## 1. 不列为本插件开发或修复任务的部分

| 项目 | 归属与已知事实 | 当前处理 |
|---|---|---|
| Git 页的暂存、提交等业务功能 | 由官方 better-sidebar 的 Git 组件及宿主接口提供；本插件复用界面。本次原生 Git 页提交 UI 已通过。 | 不另做 Git 实现，不继续扩展为完整 Git 产品验收；保留已完成的集成检查。 |
| 原生右栏编辑器未保存关闭确认 | 实测点击页签 × 无确认，重开只剩磁盘旧内容。该路径由原生右栏／官方编辑器组件提供，本插件没有实现编辑器关闭保护。 | 作为原生组件路径的已知行为记录，不列为指导插件必须补的功能；关闭前先保存。尚未做禁用自有插件的纯原生对照，不能声称已独立证明上游根因；也不能把此现象推广到所有编辑器入口。 |
| 宿主上下文压缩、模型服务重试的底层实现 | 指导使用宿主已有 persona／agent-loop／压缩和重试组件，具体有效配置仍会影响行为。 | 不新增指导专用压缩引擎或重试器。首轮指导的 persona、任务边界和 skill 接入仍由本插件负责；详见 [RM 验收决定](RM-ACCEPTANCE-DECISIONS.md)。 |

“复用原生组件”不等于本插件可以忽略自己造成的回归：若后续证实自有 adapter、过滤、注册或生命周期代码破坏了原生功能，应修复自有集成代码。当前不为扩大验收范围而接管原生组件维护。

## 2. 属于本插件、决定维持现状的设计

| 项目 | 当前设计与证据 | 已接受的边界 |
|---|---|---|
| 手动归档 | 调用宿主归档接口，可请求停止执行、保留历史并标为休眠；可取消归档或重新打开。正常打开一个指导侧页后再归档的关闭流程已通过。 | 保留为辅助会话管理能力，不删除、不继续扩展归档 UI。关闭页签只释放视图引用，与归档的会话状态不同。 |
| 同一指导强制重复打开到两个侧栏 pane | 这是同一个 child 的两个视图，不是普通“主会话 + 一个指导侧页”。归档状态已生效、运行实例已卸载，但只关闭一个重复页签，另一个还显示历史和输入框。清理只匹配首个视图的逻辑在自有 guide-panel 中。 | 接受这一视图残留，沿用 O15／D14 的归档可见性决定；不追加清理所有重复视图、全面禁用残留输入框等整改。未在残留输入框发送消息，不推断执行闸门已被绕过。 |
| 自动归档（O5／D27） | 保留能力，默认 `archive.auto=false`；显式开启才按 15 秒扫描。真实压力下的短延迟三档和打开视图保护已通过隔离测试。 | 保持默认关闭和当前调度，不追求阈值到点立即执行。归档不压缩上下文、不退回已消耗的 token；已释放的运行名额不因归档再释放一次。 |
| 核心会话行转圈（Q4／D29） | 沿用宿主“子智能体运行中”的显示；主会话可以独立回复。 | 保持现状，不改转圈或新增显示方案。 |
| 首轮优先、长对话与复制成本（RM-3／RM-7） | 保留指导 persona、当前问题优先的任务边界及 skill 接入，接受继承主会话上下文和成本。 | 不新增专用摘要、长对话抗漂移、token 节省或费用管理方案；完整长时 soak 与资源趋势观察为可选非阻塞项，不承诺模型绝对遵循。 |
| 模型服务错误恢复（RM-5） | 沿用宿主模型回合重试及 provider 策略。 | 接受共享机制，本轮不追加故障注入门禁；不把源码确认写成故障实测通过。 |

双 pane 归档保留的是已接受的视图清理边界；原生编辑器关闭则属于上一节的任务范围划分。两者不能合并成“本插件还有两个必须修复的问题”。
