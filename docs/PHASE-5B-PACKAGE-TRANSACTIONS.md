# Phase 5B：独立升级与包版本恢复

更新：2026-11-07。5A 真实 Edge 与独立 Electron 桌面验收通过后启动，见 [验收](../evidence/phase5-acceptance-2026-11-07/report.md)。当前进度统一见 [项目状态](../PROJECT-STATUS.md)。

## 设计

- 保留多包与独立 manager；首次安装沿用 schema 1 目录。5B 引入独立 schema 2 升级目录：精确包产物、内部 peer 要求和维护者声明的有限兼容组合。运行时只选择这些组合；不猜测任意 SemVer 组合兼容。
- 用户指定组件目标版本；在兼容组合中选择联动最少的一组，并列出保留、单独升级或必须联动的组件。只有已安装的 profile 自有组件参与升级，缺失组件先走安装，开发 link 不被隐式覆盖。
- 首次安装及升级的包固定保存到 profile `.guide-manager/package-cache/<sha256>.tgz`。恢复所需旧包在事务目录再备份一份，防止原发布目录删除后无法回退。旧版非缓存安装先拒绝升级，不在升级过程中隐式迁移已有 link。
- 确认绑定 profile 四文件、已安装 manifest、目录与来源哈希。冷执行时持有官方 profile 写锁，复用官方 pnpm；全组完成后复核实际版本、peer 约束、宿主产物和配置。包变更不隐式改变用户原有启停状态。
- 事务保存原 package.json、pnpm-lock.yaml、cordis.patch.yml、pnpm-workspace.yaml 和旧 tgz。失败恢复精确旧文件、使用旧 lock 重装依赖，再核对旧版本。恢复失败明确标记，助手不自动重启。
- 显式包版本恢复也先预览确认：仅允许恢复当前 profile 未发生额外编辑的成功事务，避免覆盖用户之后安装的其他插件或配置。恢复从事务内旧包补回稳定缓存，再按旧 lock 恢复旧包和配置；不依赖原发布目录或 registry。
- 重启后核对实际加载版本、启停状态、契约、服务与必要宿主产物；已安装到磁盘不等于已验证运行。事务与回执落盘，刷新不丢操作结果。

## 边界

首版只支持可信本地 tgz，契约 1、数据 schema 1、无升级数据迁移；包安装禁止构建脚本。不承诺逆转任意包启动代码对用户数据的副作用。registry 最新版本发现、manager 自升级、卸载和任意跨 schema 迁移不属于本轮实现。

## 验收

默认测试覆盖单组件升级、最小联动、冲突组合/未知组件/过期计划拒绝、开发 link 保护、旧包备份、失败修复、原目录删除后的恢复、恢复时配置漂移拒绝、刷新后的操作状态。真实官方包操作与真实 UI 继续在独立 home/profile 验证：1.1.0 → 测试版 1.1.1 → 恢复 1.1.0；仅测试夹具改变版本，不将其标记为正式发版。升级失败注入与原用户实例存活另行留证。
