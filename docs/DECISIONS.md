## 3. RM-3／RM-5／RM-7 的验收依据

依据用户"重视首轮指导、接受上下文复制和宿主默认机制"的决定收窄验收范围。本轮仅源码核对，无外部模型调用、无新运行测试、无生产代码或真实 profile 改动。

本机安装版 DSH 0.2.1-rc.3 的四个原生预设是 standard、ptc、minimal、cordis；均通过 dsh-agent-preset 注册、dsh-persona 贡献身份提示，使用同一 agent-loop。

| 部分 | standard / ptc / cordis | minimal | 当前 guide |
|---|---|---|---|
| 预设装配 | dsh-agent-preset | 相同 | 相同 |
| 身份提示 | dsh-persona | 相同组件，但 complete=true，关闭 runtime context | 相同组件，配置指导专用 prefix |
| 压缩后端 | dsh-compaction-basic | 相同后端 | 相同后端 |
| 工具输出裁剪 | tool-result-pruner | 未挂该 pruner | 与前三个相同组件及 8192/4096/1024 参数 |
| 模型回合重试 | Host 的 llm-retry + provider retryPolicy | 相同机制 | 相同机制，未另写指导专用重试器 |

"同一组件"不等于四种预设的所有工具、提示或行为相同；guide 与 standard／ptc／cordis 的压缩组定义一致，minimal 的组合更精简。来源快照见 [rm-research/sources](../evidence/O11-validation-2026-11-04/rm-research/sources/)，本地 guide 定义见 `guide-preset/cordis.patch.yml`。

**RM-3（压缩）**：用户理解的"对话过长后可能偏离指导"只是风险之一，原 RM-3 还包括上下文溢出、压缩失败、压缩后不能继续。四种原生预设也没有绝对防止长对话语义偏移的机制，它们与 guide 同样依靠 persona／system prompt 和宿主压缩。persona 来自预设的系统提示装配，不是只在第一条消息说一次；普通摘要压缩不等于删除预设或取消 persona。当前首轮有两层源码可确认的约束：guide 专用 persona（用户询问技能／命令／下一步时加载 guide skill 并给出建议，不执行所建议的工作；skill 缺失时明确降级），以及指导首条消息的边界提示（继承的历史是参考上下文，新的用户问题才是当前任务）。这些是模型指令约束，不是权限闸门；源码可确认装配路径，不能保证任何模型在任何输入下 100% 遵守。首轮也可能继承已很长的主会话并触发压缩，因此"只重视首轮"不等于首轮没有上下文压力。

**RM-5（重试）**：普通主会话、普通代理和 guide 的模型回合都进入宿主 agent-loop 的 agent/request-error，再由 Host llm-retry 与选中 provider 的 retryPolicy 决定重试；guide 没有独立的网络请求或重试实现。使用同一 provider route／有效配置时适用相同策略，换 provider 或改策略后次数与退避可能不同，这种差别不来自 guide preset。压缩摘要的直接 `ctx.llm.stream` 调用不经过普通步骤重试器，这是宿主原有入口差别，也不是插件额外引入的规则。

**RM-7（成本／长时）**：以 fork seed 继承主会话已完成轮次的上下文，不为首轮另设摘要优化；接受这一路径的上下文体积和模型成本，不要求 token 硬预算、费用账本或为 RM-7 单独做上下文优化；持续 30 分钟的真实模型 soak 不作为当前交付条件。成本／复制策略与资源泄漏是不同问题：接受前者不能证明 slots、监听器、标签页或内存长期没有累积，因此长时资源趋势验证列为**可选、非阻塞观察**，真实使用出现累积、卡住或性能退化时再针对复现排查。已有关闭／归档／名额等生命周期回归与修复继续保留。

| 项目 | 当前设计验收 | 历史测试事实 | 是否阻塞当前首轮方案 |
|---|---|---|---|
| RM-3 | 接受宿主压缩与 persona 机制 | 未进行完整压缩压力验收 | 否 |
| RM-5 | 接受共享宿主重试机制 | 未进行完整 provider 故障注入 | 否 |
| RM-7 | 接受复制／成本；长时验证暂缓 | 仅有 22.9 秒样本，未做完整长测 | 否 |
