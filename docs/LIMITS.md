# 限制与兼容

## 1. 支持范围

| 项目 | 支持值 |
|---|---|
| DSH | `0.2.1-rc.3`（build `be72761ee1a6736ebcdf4f3739363b083ae53c98`） |
| Cordis | `4.0.5` |
| better-sidebar | 官方 `0.28.2` |
| 平台 | Windows |
| 数据 schema | 1 |

未在支持范围内的版本：

- adapter 回退明确状态；
- panel/shield 可能进入只读、`unsupported` 或 `degraded`；
- 不承诺强制升级后仍可用；
- 升级宿主前必须按开发文档重新核验产物、契约和真实 UI。

## 2. 功能边界

已实现并可用：

- 指导会话与上下文继承；
- goal 并行准入；
- 模型投影与控制拦截；
- 结算防护；
- sidebar 局部视图与专区；
- 归档；
- 安装/升级/恢复/卸载/修复/manager 自升级；
- 公开 Release 下载与面板自动执行；
- link → Release 迁移；
- 硬中断诊断/显式恢复；
- 包缓存重建。

## 3. 未实现

- registry/git 来源迁移；
- 任意跨 schema 数据迁移；
- 缓存损坏时自动重建所有来源；
- 任意断电点的无人工自动恢复；
- 外部依赖一键代装；
- Q7 折叠/批量操作；
- npm/市场发布。

这些是明确范围，不是隐藏缺陷。需要时按实际需求立项。

## 4. 验证缺口

以下能力已实现，但尚未完整验收：

- **真实 Edge 浏览器**中的 link 来源迁移 UI；
- link 迁移后继续升级/版本恢复的真实链路；
- 迁移期间官方写锁争用和任意断电点；
- 硬中断恢复的真实进程强杀/断电注入；
- 硬中断恢复对 package/maintenance/manager 中断的真实 pnpm 现场；
- 新 DSH/Cordis/better-sidebar 版本的 G0 重验；
- 原生 Stop 的所有入口、服务关闭顺序和第三方后包装；
- O17 capacity=1 独立复测；
- 长时资源/多窗口 SSE；
- 自动归档 low 600 秒完整计时。

默认测试和隔离夹具不能替代上述现场验收。

## 5. 已接受边界

- PT-6 Windows 沙箱 PTY 暂缓；
- R5 同源 SSE 排队未复现，保持当前实现；
- RM-3/5/7 接受宿主压缩、重试和上下文复制成本；
- 原生 Git/编辑器属于 DSH 原生组件；
- 跨会话文件锁、嵌套指导不在 v1 范围；
- 关闭页签不结束会话；归档后原生 UI 仍可能打开/输入；
- 自动归档默认关闭。

## 6. 安全

- 公开源不需要 token；私有源凭据只从本机环境读取；
- 浏览器不接收凭据、任意 URL、npm spec 或脚本；
- 所有包写操作要求确认和精确计划；
- 失败恢复不保证恢复临时文件路径或 lockfile 字节；
- 不重置用户配置、会话或未知文件；
- 包为 `private:true`、`UNLICENSED`；对外再分发前需明确许可证。

## 7. 外部依赖

| 依赖 | 责任 |
|---|---|
| `dsh-better-sidebar` | 官方插件页维护 |
| `guide` skill | 用户级技能，缺失时降级 |
| skills manager | 技能设置深链，非必需 |

插件不会替这些依赖做安装/升级。

## 8. 版本策略

- manager 与六组件独立版本；
- 组件版本不保证单调：`1.1.1` / `1.2.0` 是 `codex/phase5d4-release-series` 的升级验收测试版本，主线自 `guide-v1.3.0` 起回到 `1.1.0`；版本选择只按发布清单的精确 pin 与兼容组合，不按 semver；
- 发布清单声明兼容组合，不以版本齐平代替兼容性；
- 同版本改字节拒绝发布；
- 旧版本附件保留用于恢复；
- 升级/恢复必须核对 package SHA、契约、宿主和配置；
- 发布只通过 GitHub Releases，当前不发布 npm。
