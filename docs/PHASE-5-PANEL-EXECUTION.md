## 用户流程

安装一次支持自动执行的 manager 后，在“插件 → 指导”中检查更新，选择精确版本并下载，预览版本、依赖联动和重启提示，点击“确认执行并重启”。管理器随后自动启动执行器、关闭目标 DSH、使用官方 pnpm 安装、重新启动并返回指导页，核对新 Host 中的实际版本及运行状态。下载和预览仍不改安装配置。

同一入口覆盖首次组件安装、独立或联动升级、包版本恢复、卸载、原版本修复和管理器自身升级。已有准备计划或冷开关变更可从顶部“执行并重启”预览后确认。手动命令保留在折叠的恢复入口中。

确认前必须保存工作、结束需要继续运行的任务。桌面关闭窗口会隐藏到托盘，因此执行器沿用既有按实例停止流程：尝试关闭，再停止该实例的已验证进程树，全部退出后才改包文件。不会按同名进程批量结束其他 DSH。此版本不承诺把正在运行的模型任务迁移到重启后的进程。

## 实现与故障恢复

- `execution/plan` 对已准备计划、profile 四文件、控制器运行文件及 Host 身份生成精确指纹；`start` 再验证，建立 profile 独占锁，将完整执行器复制到 `.guide-manager/controllers/<内容指纹>/`，先保存恢复命令，再创建独立 Windows 进程。
- 使用 Windows 自带 PowerShell 5.1 和 WMI 创建独立进程，不要求安装 PowerShell 7。执行器的父进程位于 DSH 树之外，管理器自升级或 DSH 退出不会顺带杀掉它。继承环境仅在内存中传递，不写入请求、启动记录或网页。
- 浏览器保存不含凭据的操作标记后，调用 `execution/ack`。服务器发送确认响应后才写执行许可。未确认、指纹变化或启动失败均不进入停机安装；执行前再次核对文件 SHA。浏览器 HTTP 接口沿用官方 connection 校验，只接受白名单字段和计划 ID，不接受任意命令、路径或包名。
- 任务状态持久化为 waiting-ack → executing → awaiting-verification → completed/failed；安装回执不等于完成。必须是新 Host、对应计划已消费、精确事务回执和健康核对通过才能标记 completed。
- 重启期间保留操作标记，使用官方持久登录 cookie 重连；移除会失效的临时 URL token。官方界面断连后可能卸载全部内容，独立的页面恢复轮询会在终态后刷新一次，再自动回到“插件 → 指导”。再次打开桌面窗口也可根据同一标记恢复。
- 桌面停止时 localStorage 可能还未写盘，因此服务端也保留“结果尚未展示”标记。新窗口从持久任务恢复导航意图，成功进入可见的指导页后调用 `execution/seen`，再清除网页标记，避免重启后丢失入口或反复弹回。
- 启动失败保留 pending，页面给出日志与恢复入口；中途失败沿用已有事务恢复策略。依赖恢复失败时保持停止，使用事先保存的 recovery.txt 和独立恢复脚本处理，不能把“重启失败”显示为成功。

## 支持边界

自动执行限已验收 Windows DSH 构建。支持普通默认桌面启动、已有匹配 launcher.json 的隔离桌面/浏览器实例，以及可严格识别的固定 loopback 地址与端口的官方 Electron Node CLI 启动。PID、创建时间、可执行文件与 Host 祖先关系必须一致；未知启动方式拒绝自动停机并保留手动入口。

manager 1.2.0 开始声明 `dshGuide.executionSchema:1`。自动升级的目标也必须声明相同协议并包含执行器，旧管理器目标可继续通过手动恢复工具处理。第一次从旧版 manager 接入新能力仍需按原方式升级一次；不能让正在运行的旧版凭空获得新接口。

这项能力不包含 link 来源迁移、任意 schema 迁移、外部技能/插件代装或跨平台安装器。外部恢复脚本继续保留，尤其用于管理器无法启动的情况。

## 功能测试

默认 `npm test` 覆盖计划指纹、确认前不执行、互斥、漂移拒绝、启动失败保留计划、新 Host 精确回执核对、HTTP 授权与输入限制、页面确认链路，以及原生 PowerShell 的状态写入和兼容性。

真实两端测试使用 `guide-manager/test/setup-acceptance.mjs` 创建全新 profile，再运行 `one-click-acceptance.py <新验收目录> web|desktop`。此测试只负责初始启动和结束清理，包操作全部从实际面板点击发起；测试程序不得代为调用助手或在重启后手动导航到指导页。记录公开下载、SHA、执行器父 PID、原生 PowerShell 版本、重启后健康状态与截图。`--derive-web-record` 另验证首次自动识别 CLI；管理器升级使用包含执行协议的明确目标包。
